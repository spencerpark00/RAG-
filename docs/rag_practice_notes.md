# RAG 연습 회고 노트

> 가상 통신사(한빛텔레콤) 고객센터 문서 25개로 업무지식 검색 챗봇을 만들어 보며 확인한 것.
> 목적은 **구조 이해와 판단 기준 확보**. 이 코드를 실제 프로젝트로 이어 가는 계획이 아니다.
> 실제 프로젝트는 도메인 정의부터 다시 시작하므로, 이 노트의 쓸모는 ③ 결정 포인트와 ④ 킥오프 질문 목록에 있다.

---

## ① 만든 것 (한 장 요약)

```
[색인]  문서 ─ 청킹 ─ 임베딩 ─ 저장           [질문]  질문 ─(보강)─ 검색 ─ 프롬프트 ─ LLM ─ 답 + 근거
        md     섹션   bge-m3   JSON 파일                       업무용어   BM25+벡터  규칙·자료  로컬/API
               +머리말(현행/폐지)                                         (RRF)
```

| 단계 | 이번에 한 것 | 파일 |
|---|---|---|
| 청킹 | `##` 섹션 1개 = 청크 1개, 모든 청크에 `[문서번호·상태·시행일]` 머리말 | `chunk.py` |
| 임베딩·색인 | bge-m3(로컬 Ollama), 바뀐 청크만 다시 임베딩 | `embed.py`, `indexer.py` |
| 검색 | BM25(글자 bigram) + 벡터 → RRF 합침, LLM 질문 보강 | `retrieve.py`, `query.py` |
| 생성 | 자료 → 규칙 → 질문 순서 프롬프트, 근거 없으면 거부, 로컬 3b ↔ Groq | `answer.py`, `llm.py` |
| 화면 | FastAPI(SSE 스트리밍) + React, 근거 패널, 문서 관리 | `server.py`, `frontend/` |
| 평가 | 검색 적중(Hit@k)과 답변 정확성을 분리 채점 | `eval_*.py`, `experiments/` |

## ② 실험으로 확인한 사실

수치는 질문 30개(+일상 표현 15개) 기준이라 일반화에 한계가 있다. "이런 현상이 있다"는 확인용으로 본다.

| # | 확인한 것 | 근거 | 실무에서의 의미 |
|---|---|---|---|
| 1 | **검색과 생성을 따로 채점해야 원인이 보인다** | 오답 중 다수가 근거 문서를 검색해 놓고도 틀림(생성 문제) | 정확도 하나만 보면 엉뚱한 곳(검색)을 고치게 된다 |
| 2 | **청크마다 상태·시행일 머리말을 붙이면 현행/폐지 구분의 바탕이 된다** | 폐지 문서도 검색되지만 머리말로 구분 가능. 과거 시점 질문(2월 해지 → 100%)엔 폐지 문서가 필요 | 폐지 문서를 지우면 안 되고, '표시'해서 남겨야 한다 |
| 3 | **프롬프트 규칙의 위치만 바꿔도 결과가 크게 바뀐다** | 규칙을 시스템 메시지 → 자료 뒤로 옮기자 과잉 거부 14 → 2 (3b) | 작은 모델일수록 프롬프트 구조에 민감 |
| 4 | **"모른다"를 늘리면 지어내기가 줄고, 줄이면 늘어난다** | 형식 강제·예시 추가 시 거부 0이 됐지만 eSIM 절차를 지어냄 | 상담 업무에선 틀린 확답 > 모름 이 더 위험. 정책으로 정할 문제 |
| 5 | **작은 로컬 모델의 한계는 프롬프트로 다 못 메운다** | 날짜 비교 질문: 3b 거부(135초) → gpt-oss-120b 정답(2.6초), 프롬프트 동일 | 모델 선택(규모·사내 구축 가능 여부)이 품질 상한을 정한다 |
| 6 | **하이브리드 검색이 키워드 단독보다 낫다** | 1위 적중 22 → 25/27 | 동의어("위약금"↔"할인반환금")·일상 표현에 의미 검색이 필요 |
| 7 | **사용자는 문서 용어를 모른다 → 질문 보강이 효과적** | 일상 표현 15개 중 정답 문서 검색 11 → 14 | 실제 질문 로그로 측정해야 할 핵심 지표 |
| 8 | **작은 모델의 질문 보강은 부작용이 있다** | 3b 보강 시 정확한 질문의 1위 적중 25 → 22, 7b는 유지 | 보강 모델 선택도 평가 대상 |
| 9 | **temperature 0이어도 실행마다 1~2문항이 흔들린다** | 같은 설정 반복 실행 시 판정 변동 | 버전 비교는 여러 번 돌려 차이가 흔들림보다 큰지 확인 |
| 10 | **못 찾았을 때의 화면이 사용성을 좌우한다** | "확인할 수 없습니다"만으론 문서에 없는지/검색 실패인지 구분 불가 → 추천 질문 추가 | 거부 응답도 설계 대상 |

### 실행 환경에서 겪은 함정 (다시 만나기 쉬운 것)

| 증상 | 원인 | 해결 |
|---|---|---|
| `npm install` 실패(EINVALIDTAGNAME) | 맥 zsh는 명령 뒤 `# 설명`을 주석으로 안 봄 | 명령과 설명을 분리 |
| Groq 호출 SSL 인증서 오류 | python.org 맥 Python에 인증서 목록 없음 | certifi 사용 |
| 키를 넣었는데 모델 목록에 없음 | 서버는 시작할 때만 `.env`를 읽음 | 서버 재시작 |
| 하이브리드 검색 실패 | 질문 임베딩에 로컬 Ollama 필요 | 꺼져 있으면 키워드 검색으로 자동 대체 |
| 3b 답변에 `。` 등 중국어 문장부호 | 모델 특성, 재작성 요청으로도 안 고쳐짐 | 후처리로 치환 |

## ③ 단계별 결정 포인트 (프로젝트에서 다시 정할 것)

| 단계 | 이번 선택 (더미 데이터 기준) | 실제 프로젝트에서 확인할 것 |
|---|---|---|
| 문서 수집 | md 25개, 직접 제공 | 원천 시스템(사내 위키·그룹웨어·파일서버), 형식(PDF·HWP·엑셀·이미지), 양, 접근 권한 |
| 전처리·청킹 | `##` 섹션 단위, 표는 자르지 않음 | 문서 구조가 일정한가? 표·스캔본·첨부 비중, 청크 크기 실험 필요 |
| 메타데이터 | 문서번호·현행/폐지·시행일 | 버전 관리 주체, 개정 이력 관리 방식, 부서·권한·대상 고객군 |
| 임베딩 | bge-m3 (로컬) | 한국어·도메인 용어 성능 비교, 사내 구축 가능 여부, 재색인 비용 |
| 저장소 | JSON 파일 | 벡터 DB 선택(규모·운영 인력·기존 인프라) |
| 검색 | BM25 + 벡터 + RRF, 질문 보강 | 재순위(reranker), 메타데이터 필터(현행만/부서별), 동의어 사전 |
| 생성 모델 | 로컬 3b / Groq(외부 API) | **외부 API 허용 여부**, 사내 GPU, 응답 시간 목표, 비용 |
| 답변 정책 | 근거 없으면 거부 + 추천 | 일반 지식 허용 범위, 거부 시 안내(담당 부서 연결 등), 출처 표기 방식 |
| 화면·연동 | 웹 단독, 브라우저 저장 | 기존 상담 시스템 연동, SSO, 대화 로그 저장·감사 |
| 평가 | 질문 30개, 키워드 자동 채점 | 실제 질문 로그로 평가 세트 구축, 사람 검수 기준, 운영 중 피드백 수집 |

## ④ 킥오프·도메인 정의 때 물어볼 질문

### 사용자와 목적
- 주 사용자는 누구인가? (상담사 / 고객 / 내부 직원) → 답변 말투, 허용 범위, 화면이 달라진다
- 챗봇이 줄여야 하는 것은? (검색 시간, 신입 교육 기간, 오안내 건수 …) → 성공 지표가 된다
- 지금은 그 업무를 어떻게 처리하나? (매뉴얼 검색, 선배에게 문의, 위키 …)

### 문서
- 대상 문서의 종류·형식·분량은? 가장 많이 찾는 문서 Top 10은?
- 문서가 얼마나 자주 바뀌나? 현행/폐지(개정 이력)는 누가 어떻게 관리하나?
- 문서끼리 충돌할 때(비교표 vs 개별 문서) 우선순위 규칙이 있나?
- 권한별로 볼 수 있는 문서가 다른가?

### 답변 정책
- 문서에 없는 질문엔 어떻게 해야 하나? (거부 / 일반 지식 허용 / 담당자 연결)
- 틀린 답의 위험도가 높은 영역은? (요금·위약금·개인정보 …) → 더 엄격히 다룰 영역
- 답변에 출처(문서명·조항)를 반드시 보여야 하나?

### 기술·보안
- 외부 LLM API를 쓸 수 있나, 사내 구축만 가능한가?
- 쓸 수 있는 인프라(GPU, 벡터 DB, 기존 검색엔진)는?
- 질문·답변 로그를 저장해도 되나? (개인정보 포함 가능성)

### 평가
- 실제 질문 데이터(상담 로그, FAQ 조회 기록)를 받을 수 있나?
- 정답 판정은 누가 하나? 합격 기준은?

## ⑤ 이 연습에서 가져갈 것 / 버릴 것

| 가져갈 것 (방법) | 버릴 것 (구현) |
|---|---|
| 검색·생성 분리 평가, 함정 문항(폐지 규정)·답없음 문항을 섞은 평가 세트 | 순수 Python BM25, JSON 벡터 저장 |
| 청크 머리말로 메타데이터를 검색·생성 양쪽에 전달하는 방식 | 더미 문서에 맞춘 `##` 섹션 청킹 규칙 |
| 실험은 한 번에 하나씩 바꾸고, 반복 측정으로 흔들림 확인 | qwen2.5:3b 전용 프롬프트 튜닝 |
| 거부 응답·근거 표시까지 포함한 사용자 경험 설계 | 화면 세부 디자인 |
| 일상 표현 질문 세트로 검색 강건성 측정 | Groq 무료 API (실데이터에는 사용 불가) |
