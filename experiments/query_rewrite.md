# 질문 보강(재작성) 실험

- 방법: 검색 전에 LLM이 "문서 목록(제목·섹션·표 핵심어)"을 보고 질문을 업무 용어 검색어로 바꿈 → 원래 질문과 검색어의 하이브리드 검색 결과를 RRF로 합침 (`query.py`)
- 질문 세트: 일상 표현 15문항(`colloquial_questions.csv`, 문서 용어를 쓰지 않은 질문) + 기존 평가 27문항(근거 문서가 있는 것)
- 환경: 클라우드 컨테이너 CPU. Groq 키가 없어 로컬 qwen2.5:3b / 7b로 측정 (Groq gpt-oss-120b는 맥에서 수동 확인만)

## 결과 (하이브리드 검색, 정답 문서가 상위 k개 안에 있는가)

| 세트 | 지표 | 보강 없음 | 보강 (3b) | 보강 (7b) |
|---|---|---|---|---|
| 일상 표현 15 | Hit@1 | 10 | 11 | 11 |
| | Hit@5 | 11 | **14** | **14** |
| 기존 평가 27 | Hit@1 | 25 | **22** | 25 |
| | Hit@5 | 27 | 27 | 27 |
| 문항당 재작성 시간 | | - | 약 5초 | 약 11초 |

## 해석

- 일상 표현 질문은 보강으로 11 → 14개가 정답 문서를 찾았다. 3b와 7b가 같은 수치 → 효과의 대부분은 모델 크기보다 '문서 목록을 함께 준 것'에서 나옴.
- 3b는 이미 업무 용어로 쓴 질문에서 1위 정확도를 떨어뜨렸다(25 → 22). 7b는 떨어뜨리지 않았다 → 작은 모델의 검색어는 엉뚱한 문서를 끌어올 수 있음. 로컬 모델에서 보강을 기본 꺼짐으로 둔 근거.
- 검색어가 맞아도 순위가 낮은 경우가 있다: C01 7b 검색어 "일시정지 분실 도난"인데 정답 문서 11은 4위. 원래 질문의 결과(본인인증 문서)가 RRF에서 같은 무게로 합쳐지기 때문. 다음 개선 후보: 보강 검색어 결과에 가중치를 더 주기.
- 문서 목록 처음 버전(제목·섹션명만)에는 일시정지 문서에 '분실·도난'이라는 말이 없어 3b가 "번호이동"으로 바꿨다. 표 첫 열 값(분실·도난, 해외 체류 등)을 목록에 넣은 뒤 개선됨.
